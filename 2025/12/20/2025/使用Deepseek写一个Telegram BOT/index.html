使用Deepseek写一个Telegram BOT

发表于2025-12-20|更新于2025-12-22|项目实践
|总字数:1.4k

本次AI编写程序在VsCode上使用Cline插件完成，AI使用Deepseek-REASONER-V3

在开始之前，首先也是最重要的是明确自己的需求，之后使用AI变成便如鱼得水

项目概述

该项目主要实现一个telegram bot可以记录群组中的媒体消息、管理群组、方便用户查询群组消息等。

项目需求

大概

  1. 记录群组中包含文字信息的视频、图片或文档消息（下面统称为媒体消息）
  2. 管理群组：记录入群成员，在成员推出群组后将其拉黑
  3. 用户私聊机器人时，将匹配到文字的群组消息返回给用户
  4. 处理用户的一些请求：媒体合并、查询特定群组、频道的消息等

具体实现

程序运行流程

程序启动后先清空AcceptMessage数据库，然后开启一个线程每个一小段时间重新处理该数据库中处理失败的数据，主程序就等待bot接收消息。

当bot收到消息后，会自动开启一个线程来处理这条消息（处理完成后关闭该线程）：首先，将收到的消息先存入AcceptMessage数据库中，然后根据消息是在群聊中发送的还是个人发送给bot的分别处理。

处理群聊消息

群聊中的消息只处理媒体消息和群成员加入、退出消息，包含群聊中发送的媒体消息和编辑的媒体消息

发送的媒体消息

发送的媒体消息如果不包含文本信息就忽略它，并把AcceptMessage数据库中该消息的state设置为1，否则将消息自动拆分并存入DataStorage数据库中，需要注意的是：数据库中的等级为文本的最后#后面的字母S、A、B或C。

编辑的媒体消息

编辑的媒体消息把消息的文本替换到DataStorage数据库匹配chat_id、message_id的text中，如果该消息的文本为空，那么将该数据在数据库中删除。

用户端

  1. 媒体合并：当用户输入/MediaGroup时，机器人进入等待，当用户输入/EXIT时或者机器人等待时间超过5分钟后，机器人按照用户发送媒体的顺序将这些媒体每10个合并为一个组，依次返回给用户。
  2. 指定群组：用户输入/GroupChatSearch时，机器人返回数据库中的所有不重复的群组ID给用户，用户输入/GroupChatSearch且后面跟着ID时，机器人判断ID是否存在，如果存在，用户后面所有的数据查询都将只局限于该ID所在的群组内进行查询，直到用户输入/EXIT退出该模式。
  3. 数据查询：根据用户输入的文字进行查询
    1. 当用户输入的文字最后带有 -s、-a、-b、-c时，说明用户只想查询S、A、B、C等级的数据，其他的可以忽略。
    2. 当用户输入的文字最后带有s-、a-、b-、c-时，说明用户只想根据等级S>A>B>C查询小于等于输入文字的数据。相反，当用户输入的文字最后带有s+、a+、b+、c+时，说明用户只想根据等级S>A>B>C查询大于等于输入文字的数据。
  4. 数据排序：
    1. 如果随机排序是打开状态，将查询到的数据进行随机排序（用户可以输入/setting openRandomSearch或者/setting closeRandomSearch进行打开或关闭随机排序）
    2. 如果等级排序为打开状态，根据数据等级S>A>B>C进行排序（用户可以输入/setting openLevel或者/setting openLevel进行打开或关闭等级排序）
  5. 数据打印：
    1. 打印的格式如下：数据以文本加编号的形式打印在文本框中，每页最多打印15个。在文本框的下面有着对应文本编号的编号按钮，每行最多5个编号按钮，最多三行一共15个编号按钮。在编号按钮的下面有两个按钮：上一页和下一页，当数据超过一页显示的上限，可以按上一页、下一页按钮查看上一页、下一页，文本框中的文本会刷新，下面的按钮也跟着刷新。

数据库

数据库使用SQLite数据库，所有数据库有关的操作均不区分字母的大小写

AcceptMessage（接受消息数据库）

名字 注释
id 编号（自动+1，初始为1）
text 接受到消息的文本信息
state 处理状态（0：处理失败；1：处理成功）

DataStorage（数据存储数据库）

名字 注释
id 编号（自动+1，初始为1）
message_id 接受到的消息在群组中的ID
chat_id 群组ID
file_id 媒体文件id（存储媒体唯一地址id，方便后面bot直接调用发送该媒体给用户）
text 接受到的媒体消息附带的文本
level 等级（文本最后面的带#的字母，等级顺序为S>A>B>C）

ChatUser（群聊用户）

名字 注释
id 编号（自动+1，初始为1）
chat_user_id 用户ID

Chat（群聊）

名字 注释
id 编号（自动+1，初始为1）
chat_id 群聊ID

ChatUserBan（群聊用户封禁）

ChatUserBan数据库包含Chat数据库中的chat_id和ChatUser数据库中的chat_user_id，另外还多了下面两项：

名字 注释
id 编号（自动+1，初始为1）
state 封禁状态（0：正常未封禁；1：封禁）
