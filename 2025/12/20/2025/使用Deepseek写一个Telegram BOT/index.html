使用Deepseek写一个Telegram BOT

发表于2025-12-20|更新于2025-12-23|项目实践
|总字数:2.7k

**本次AI编写程序在VsCode上使用Cline插件完成，AI使用Deepseek-reasone-V3**，使用nodejs完成本次代码编写。

在开始之前，首先也是最重要的是明确自己的需求，之后使用AI变成便如鱼得水

项目概述

该项目主要实现一个telegram bot可以记录群组中的媒体消息、管理群组、方便用户查询群组消息等。

项目需求

大概

  1. 记录群组中包含文字信息的视频、图片或文档消息（下面统称为媒体消息）
  2. 管理群组：记录入群成员，在成员推出群组后将其拉黑
  3. 用户私聊机器人时，将匹配到文字的群组消息返回给用户
  4. 处理用户的一些请求：媒体合并、查询特定群组、频道的消息等

具体实现

程序运行流程

bot收到消息后，开启一个线程来处理这个消息，首先判断消息是来自个人用户还是群聊、频道（以下简称群聊），分别为他们进行不同处理。

处理群聊消息

群聊中的消息只处理媒体消息和群成员加入、退出消息：

  1. 发送的媒体消息：如果不包含文本信息就忽略它，否则将消息包含的信息按对应关系存入DataSave数据库中，需要注意的是：数据库中的等级为消息文本结尾的#S、#A、#B或#C（S>A>B>C），如果没有那么默认为#C。还有，接受到的群组ID和应用是的是不一致的，需要转化为默认可以使用的群组ID在存储到数据库中。数据处理完毕后，在群聊中发送【数据已收录】，并在3秒后删除刚刚发送的消息。
  2. 编辑的媒体消息：通常编辑的消息仅为文本消息，把消息的文本替换到DataSave数据库匹配chat_id、message_id的text中，并且在群聊中发送一个在3秒后自动删除的【数据已修改】。如果该消息的文本为空，那么将该数据在数据库中删除，并且在群聊中发送一个在3秒后自动删除的【数据已删除】。
  3. 群成员加入：将群成员的ID存入ChatUser数据库中的chat_user_id中（如果数据库中没有这个ID的话）
  4. 群成员退出：匹配ChatUserBan数据库中的chat_user_id、chat_id，将state设置为1，并将其在该群组中封禁。

处理个人消息

处理个人消息包含诸多事宜：

  1. 处理用户发送的指令：

    共有如下指令：

    指令 注释
    /help 帮助
    /media_group 多个单一媒体消息合并成组
    /exit 退出
    /search_chat 查找指定群组的消息
    /random 随机发送
    /clear_database 清理数据库
    /setting open_search_level 打开搜索按级别排序
    /setting close_search_level 关闭搜索按级别排序
    /setting open_search_random 打开搜索随机排序
    /setting close_search_random 关闭搜索随机排序
    1. /help：回复用户：【暂时没有帮助信息】
    2. /media_group：开启媒体合并模式，接收用户发送的多个媒体，当用户发送**/exit**或者时间超过1分钟，退出媒体合并模式，并将接收到的媒体按照10个一组的格式，按顺序发还给用户
    3. /search_chat：查找指定群组的消息，将Chat数据库中的所有不重复的chat_id按照一定格式发送给用户
    4. /random：按照处理用户发送的文本消息的格式随机发送Datasave数据库中的15条数据给用户
    5. /clear_database：清理数据库，删除DataSave数据库中所有text为空的项
    6. /setting open_search_level ：打开搜索按级别排序，回复用户【按级别排序已打开】
    7. /setting close_search_level ：关闭搜索按级别排序，回复用户【按级别排序已关闭】
    8. /setting open_search_random ：打开搜索随机排序，回复用户【搜索随机排序已打开】
    9. /setting open_search_random ：关闭搜索随机排序，回复用户【搜索随机排序已关闭】

  2. 处理用户发送的文本消息

    根据用户发送的消息在DataSave数据库中的text里查找匹配数据（不区分大小写），并根据是否按照级别排序、是否随机排序等，将找到的数据按照特定的格式发送给用户，下面是对格式和查找条件的进一步说明：

    1. 如果用户发送的文本消息末尾带-s、-a、-b、-c（不区分大小写），说明用户只想查找s、a、b、c级别的数据；如果消息末尾是s+、a+、b+、c+，说明用户想要查找的是级别大于等于输入字母的数据（S>A>B>C），相反如果末尾是s-、a-、b-、c-，那么用户想要查找的数据为小于等于输入换字母的

    2. 发送的格式：

      1. 发送的消息每次只展示15条数据库查找到的信息，将他们依次添加编号后，添加t.me/c/chat_id/message_id超链接，格式如下：

        1. [xxx](t.me/c/chat_id/message_id)

        2. [xxx](t.me/c/chat_id/message_id)

          ….

      2. 在发送的消息下面还有快捷按钮，对应上面消息编号，每行5个，最多3行15个按钮，点击按钮机器人发送该按钮对应编号的媒体。在最下面有上一页、下一页按钮，方便在数据库查到多条数据是翻页查看。

数据库

使用lowDB数据库，所有数据库有关的操作均不区分字母的大小写

DataSave（数据存储数据库）

名字 注释
id 编号（自动+1，初始为1）
message_id 接受到的消息在群组中的ID
chat_id 群组ID
file_id 媒体文件id（存储媒体唯一地址id，方便后面bot直接调用发送该媒体给用户）
text 接受到的媒体消息附带的文本
level 等级（文本最后面的带#的字母，等级顺序为S>A>B>C）

ChatUser（群聊用户）

名字 注释
id 编号（自动+1，初始为1）
chat_user_id 用户ID

Chat（群聊）

名字 注释
id 编号（自动+1，初始为1）
chat_id 群聊ID

ChatUserBan（群聊用户封禁）

ChatUserBan数据库包含Chat数据库中的chat_id和ChatUser数据库中的chat_user_id，另外还多了下面两项：

名字 注释
id 编号（自动+1，初始为1）
state 封禁状态（0：正常未封禁；1：封禁）

下面经过几个小时一点点添加需求，Deepseek生成的Telegram BOT:

Telegram Bot Channel

基于 Node.js 和 Telegraf 框架的 Telegram 机器人，用于记录群组中的媒体消息、管理群组，并提供消息查询功能。

功能特性

群组消息处理

  • 记录包含文本信息的视频、图片或文档消息
  • 自动提取消息等级（#S、#A、#B、#C）
  • 处理编辑的媒体消息（更新或删除）
  • 记录入群成员并在成员退出后封禁

个人用户功能

  • /help - 获取帮助信息
  • /media_group - 多个单一媒体消息合并成组
  • /exit - 退出当前模式
  • /search_chat - 查找指定群组的消息
  • /random - 随机发送15条数据
  • /clear_database - 清理数据库（仅管理员）
  • /setting - 搜索设置（按级别排序、随机排序）

文本搜索

  • 支持按文本内容搜索
  • 支持等级过滤（-s、-a、-b、-c、>a、<b等）
  • 分页显示结果，每页15条
  • 支持点击按钮直接发送对应媒体

数据库结构

DataSave（数据存储数据库）

字段 说明
id 编号（自增）
message_id 消息在群组中的ID
chat_id 群组ID
file_id 媒体文件ID
text 媒体消息附带的文本
level 等级（S、A、B、C）

ChatUser（群聊用户）

字段 说明
id 编号（自增）
chat_user_id 用户ID

Chat（群聊）

字段 说明
id 编号（自增）
chat_id 群聊ID

ChatUserBan（群聊用户封禁）

字段 说明
id 编号（自增）
chat_id 群聊ID
chat_user_id 用户ID
state 封禁状态（0：正常，1：封禁）

使用说明

1. 将机器人添加到群组

  • 确保机器人具有删除消息和管理员权限
  • 机器人会自动记录群组中的媒体消息

2. 私聊机器人

  • 发送 /help 查看可用命令
  • 发送文本消息进行搜索
  • 使用 /random 获取随机数据

3. 管理员功能

  • 设置 ADMIN_ID 环境变量以启用管理员命令
  • 使用 /clear_database 清理空文本数据

项目结构

注意事项

  1. 权限要求：机器人在群组中需要以下权限：

    • 删除消息
    • 封禁用户（用于自动封禁退出成员）

  2. 数据库：使用 SQLite 数据库，数据存储在 database.sqlite 文件中

  3. 性能考虑：

    • 搜索结果分页显示（每页15条）
    • 自动删除系统消息（3秒后）

  4. 安全性：

    • 敏感配置存储在环境变量中
    • 管理员命令需要验证用户ID

故障排除

常见问题

  1. 机器人无法启动

    • 检查 BOT_TOKEN 是否正确
    • 确保已安装所有依赖：npm install

  2. 数据库操作失败

    • 检查是否具有写权限
    • 确保数据库文件未被锁定

  3. 机器人不响应群组消息

    • 检查机器人是否已添加到群组
    • 确认机器人具有适当的权限

日志查看

程序运行时会输出日志到控制台，包括：

  • 数据库连接状态
  • 收到的消息类型
  • 错误信息
